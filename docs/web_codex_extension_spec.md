## 1. 目的と引き継ぎ指示

既存の動画制作テンプレートとスクリプト群を拡張し、ブラウザのチャットに台本・音声・背景素材を添付して動画を生成し、会話で修正・再生成できる試作を実装する。

単に完成動画を見せるだけでなく、「字幕を大きく」「最後の説明を短く」「この形式を保存」と指示して成果物を調整できるところまでをデモにする。Python一つにまとめる必要はない。既存Python処理を活用し、WebとCodex連携に適した技術を併用する。

本書を渡された実装担当は、対象のAGENTS.mdと最新コードを再確認し、本書との差分を把握して追加開発を進める。既存の案件素材・設定・スクリプトを不用意に上書きしない。本書の構成案は既存実装に合わせて調整可能だが、受入条件は満たすこと。

元の募集案件の「Windows 11でbatを実行して検収」をそのまま受託する計画ではない。今回の目的は、仮想サーバ＋外部AI API＋チャット操作の別案を体験できる試作。契約納品条件との同等性は主張しない。

## 2. 決定事項・推奨案・未確定事項

### ユーザー要望として決まっていること

- このフォルダを拡張する。
- 画面はチャットと添付が中心。
- 裏でPython等を実行し、Codexでプログラムの調整もできる構成。
- 仮想サーバと複数AI APIを組み合わせる。
- 読み上げは「さくらのAI EngineのVOICEVOX」、文字起こし・管理役はOpenAI系を想定。
- ローカルCodexでも可能な処理を、ブラウザから試せる形で示したい。

### 実装の推奨初期値

- 単一利用者、ログイン付きの限定デモ。
- Linux仮想サーバ、CPU版FFmpeg。GPU前提にはしない。
- Pythonバックエンド＋永続ジョブワーカー＋SQLite＋ローカル作業ストレージ。
- Codex App Serverとの接続は薄いアダプターに閉じ込める。必要ならNode.jsを併用する。
- Codexを会話・作業管理・コード調整に使用。別の管理LLMを必須にしない。
- 通常の生成は検証済みPythonを実行し、コード修正は必要なときだけ行う。
- 1920×1080、30fps、H.264/AAC、MP4を基本。縦型は設定切り替え。
- 最初は短尺で確認し、最後に10〜15分動画で通し検証する。

### 実装時に確定すること

- サーバ契約・CPU/RAM/容量、公開URL、認証方式、予算上限。
- OpenAIの利用モデル、認証方式、各APIの利用可能な音声・制限。
- 長尺生成の許容時間、保存期間、添付サイズ上限。
- 公開・有料API実行に必要な権限。未確定でもモック・ローカル実装は先行できる。
- 上記は仮定を設定や文書に明記し、実測や利用者の回答で更新する。

## 4. Web画面

基本レイアウト:

~~~text
案件一覧 | チャット・添付                  | プレビュー
         | 台本と背景を添付                | 動画プレイヤー
         | 「この台本で動画を作って」      | シーン・字幕一覧
         | 処理状況／エラー／再試行        | バージョン一覧
         | 入力欄＋添付＋送信              | ダウンロード
~~~

必須操作:
1. 案件を作成し、過去の会話・素材・成果物を開く。
2. 台本TXT、既存TSV、音声WAV/MP3/M4A、背景PNG/JPEG/MP4を添付する。
3. 台本・素材・希望をチャットで指定し、シーン構成と読み上げ／字幕を確認できる。
4. 初回は生成前に原稿・シーンを提示する。利用者が既に原稿を確定して生成を指示した場合は同じ確認を繰り返さない。
5. 「文字起こし中／原稿整理中／音声生成 3/12／動画合成中」等、実処理に基づく進捗を表示する。
6. 実行を中止・再試行できる。画面の再読込・切断でジョブを消さない。
7. 完成動画をその場で再生し、字幕・台本・区間音声を確認できる。
8. チャットで修正し、新しい成果物バージョンを生成する。以前の完成品へ戻せる。
9. MP4、字幕ASS/SRT、TSV、確認HTML、設定・利用素材メモを取得できる。

詳細設定は折りたたみ式でよい。API名や内部ログを通常操作の中心にしない。字幕書式・声・速度・画面比率・背景・BGMは設定パネルでも変更可能にする。
失敗時は利用者向けの原因と次の操作を表示し、秘密情報を含まない詳細ログを別に用意する。

## 5. 実行構成とデータ管理

ブラウザ → Webバックエンド → 案件・会話・ジョブの永続化 → ワーカー → Python/FFmpeg・音声API。
Codexアダプターは会話を受け、案件内の素材・原稿・設定を読み、処理を呼び出し、必要なら専用作業コピーのコードを編集する。

- 動画生成をHTTPリクエスト内で最後まで待たない。
- ジョブ状態: queued / running / succeeded / failed / cancel_requested / cancelled。
- 再起動後のrunningジョブを検出し、実プロセスの確認後に再開または失敗として回復する。
- 送信の重複で同じ有料生成を重ねない。ジョブID・入力ハッシュ・完了済み区間を保存する。
- 初期同時実行数は1。案件間のファイル混在を防ぐ。
- 進捗はSSEまたはWebSocketで配信し、再接続時は保存状態から復元する。
- API呼び出しの時間制限・429/5xxの回数制限付き再試行・中止処理を持つ。

案件ごとに uploads、原稿、設定、音声、字幕、動画、review、logs、versions を保持する。
Web用正本は構造化JSONとし、既存TSVとの対応を明示する。各区間に安定ID、scene_id、読み上げ文、表示文、背景asset_id、音声asset_id、実測長を持たせる。
会話の記憶だけに依存せず、確定した設定・台本・成果物をファイルとDBに残す。成果物には入力・設定・コード版・モデル名を紐付ける。

## 6. AI APIと字幕・動画処理

### 文字起こし

- 音声入力時のみOpenAI音声認識APIを呼ぶ。テキスト台本を文字起こしAPIに送らない。
- 認識モデル・出力形式は設定化し、タイムスタンプ対応を実装時の公式仕様で確認する。
- 元音声の時刻は入力整理用。新たに生成したVOICEVOX音声の字幕時刻として流用しない。
- 音声の容量・形式を確認し、必要なら圧縮・分割し、区間の順序を維持する。

### 読み上げ

- 主経路はさくらのAI EngineのVOICEVOX音声合成API。
- 2026-09-09参照の公式ガイドでは /v1/audio/speech、WAV出力、1回1000文字程度の制限。実装時に最新仕様と利用可能話者を再確認する。
- 文・字幕区間で分割生成し、成功済み音声を保存・再利用する。
- ローカルVOICEVOXのaudio_query/synthesisと、さくらのAPIは別アダプターにする。単純なURL差し替えで同じパラメーターが使えると仮定しない。
- ローカルURLは設定可能にする。既存既定50021と元募集の5021を混同しない。
- 読み上げ文と字幕表示文を分け、固有名詞の読み修正を保持する。

### 字幕同期と合成

- 原稿を読みやすい短い区間に分け、区間ごとに音声を生成する。
- ffprobe等による音声の実測長と挿入した間から累積タイムラインを作る。
- 字幕はその区間に表示する。文字数による比例配分だけで「正確な発声同期」と呼ばない。
- 初期版は区間単位の同期。単語ハイライトや音素単位の同期は範囲外。
- 字幕改行、最大行数、フォント・大きさ・色・縁・位置・余白を外部設定化する。
- 背景は静止画とループ動画。背景動画の音声は既定で無効にし、別途BGMを指定可能にする。
- 縦横比に応じたcrop/余白方針を設定化する。日本語フォントを実行環境に用意する。
- 全区間の音声形式を正規化し、結合後の長尺で累積ズレ・音切れを確認する。
- 字幕デザインだけの変更では音声を再生成しない。原稿の一部変更は影響区間の音声と以降のタイムラインを更新する。

## 7. Codex連携

- Codex App Server等の公式組み込み手段を使用し、実装時の仕様を確認する。
- Web案件IDとCodexの会話IDを対応づけ、途中再開・進捗・完了・失敗をWeb側へ反映する。
- 添付はサーバの案件領域に保存し、その案件内の参照として渡す。音声認識・動画処理はツール経由で行う。
- 通常操作には create_project、read/update_script、update_config、start_render、get_job、cancel_job、list_artifacts 相当の明確な操作を用意する。
- 字幕サイズ・声・背景などはまず設定変更。未対応の要求だけコード編集へ進む。
- コード編集は案件専用の作業コピーで行い、変更差分・検証結果・使用版を保存する。稼働中の共通サービスを会話のたびに書き換えない。
- コード変更後は小さな試作動画で検証してから本生成する。失敗時は直前の動作版に戻せる。
- モデルへの要求とサーバの実行権限は別。モデルが文章で完了と述べただけでジョブ成功にせず、終了コードと成果物を確認する。
- 自前Webから現在のデスクトップCodex画面を遠隔操作する方式は採らない。
- APIキー方式かログイン方式か、対象モデル・課金・利用条件を公式仕様で確認する。既存ChatGPT契約だけで第三者向けWebサービスの実行費用を賄えると仮定しない。

## 8. 実行範囲・秘密情報

コードを実行・編集するWebであるため、限定デモでも次を実装する。

- Web認証、案件所有者チェック、案件ディレクトリへのアクセス制限。
- Codex/Pythonを専用ユーザーまたはコンテナで動かし、ホスト全体や他案件への書き込みを与えない。
- APIキーはサーバの秘密情報管理または実行時注入に置き、Codexが読む案件ファイル、会話、Git、ZIP、ログに入れない。
- 生成APIは秘密情報を保持するバックエンド経由で呼べるようにする。
- 添付の名前をそのままシェル命令やパスに連結しない。型・容量・実体と展開先を確認する。
- 添付内の文章をサーバ管理命令として扱わない。
- API利用額・再試行・実行時間・保存容量に上限を設定する。
- YouTube投稿、一般公開、外部送信、サーバ契約は初期版の自動処理に含めない。

## 10. 受入条件

- 台本＋背景から短尺MP4が生成され、ブラウザで再生・ダウンロードできる。
- 音声添付から文字起こし→原稿整理→さくら読み上げ→字幕付き動画が生成される。
- 「字幕を大きく」で書式だけ更新され、音声APIを不要に再呼び出ししない。
- 一文の修正で影響区間を再生成し、元の成果物を残す。
- コード変更が必要な小さな要求を一つ実施し、差分・検証結果・新しい動画を画面で確認できる。
- 中止、API失敗、再試行、ブラウザ再読込後の復帰を実際に確認する。
- 10〜15分の横型動画で、冒頭・中間・末尾の字幕区間と音声の対応、音切れ、字幕のはみ出しを目視・試聴確認する。
- 暫定目標として、字幕イベントと生成区間の開始・終了は合成後タイムラインから100ms以内、末尾の累積ズレ200ms以内を計測する。発声開始と区間内の無音は別に記録する。未達なら測定値と原因を報告する。
- ffprobeで解像度・映像/音声トラック・再生時間を検証する。HTTP 200やファイル存在だけで成功にしない。
- APIキーが会話・ログ・成果物に出ず、他案件や指定領域外へアクセスできないことを確認する。
- モック検証と実API検証を分け、未実施を成功と書かない。
- サーバ構成・生成時間・使用モデル・処理文字数等の実測を残す。API料金は確定請求と推定を分ける。
